# Translations

Aha has a small message catalogue (`aha.i18n`) rather than gettext tooling: JSON files in
`src/aha/locales/`, one per language, shipped inside the package.

## What is translated

- **Command names and descriptions**, through Discord's own localization fields. discord.py marks every command name and description
  translatable on its own; the catalogue's `commands` map is keyed by the **English description**. `aha sync` sends the
  localizations and compares against them, so an unchanged translation never causes a re-sync.
- **Replies that use `t(key, locale, **values)`**: today `/ping`, `/coin`, every error reply, and
  `/remind`, `/reminders`, `/unremind`, `/config`, `/configure`, `/forgetme`, `/roll`, `/time`,
  `/8ball` (including its twenty answers), `/countdown`, `/privacy`, `/help`'s empty states and the
  poll/reaction messages. Still literal: the `/about` fields, `/url` previews, `/poll` option errors
  and the `/sync` operator command. The rest of the bot's strings are still literals and move over a command at a
  time (new commands should use the catalogue from the start).

## Which language a reply uses

The invoking user's Discord client language (`interaction.locale`), else the server's preferred
language, else `en-US`. A message (`@Aha ...`) invocation has no locale and gets `en-US`. A per-server
override can use the reserved `guild_settings.locale` column later; it is not wired yet.

## Never fails

Lookup goes `de-AT` -> `de` -> `en-US`. An unknown key returns the key (and logs it); a translation
whose placeholders do not fit falls back to the base text. A bad translation cannot break a command.
Translations longer than Discord's 100-character description limit are ignored.

## Adding a language

1. Copy `src/aha/locales/de.json` to `<locale>.json` (the file name is Discord's locale code, such as
   `fr`, `pt-BR` or `zh-CN`; see `discord.Locale`).
2. Translate `messages` (keep every `{placeholder}`; a test compares them with `en-US`) and, in
   `commands`, any descriptions you want localized (a test checks each key is a real command's
   English description and the text fits Discord's limit).
3. Run the tests, then `aha sync --dry-run` to see the localization changes.

## Adding a string

Put the English text in `en-US.json` under a dotted key (`feature.thing`), call `t("feature.thing",
locale_of(ctx), name=...)`, and add translations as available. Never build a sentence from translated
fragments; give each sentence its own key.
